C言語の名前空間。

C言語には四つの名前空間がある。
ラベル       : gotoで使うラベル名
タグ         : struct, union, enumのタグ名
メンバ名     : 構造体や共用体の中の変数名
通常の識別子 : 変数名、関数名、typedef名、列挙定数

なので、今回は、typedefで、変数名、関数名、の名前を一括で管理する新しいリストも必要になる。


## コンパイラ実装の最大の壁

typedefを実装する時、「Cの文法は、文脈自由文法ではない」という呪いに直面する。

これをLexer Hack( typedef-name problem)と呼ぶ

A *b

Aがtypedef名なら「型Aのポインタ変数bの宣言」
Aが変数名なら　「変数Aと変数bの掛け算」

変数名とtypedef名は、同じ名前空間にある。

typedefの文法

1. 基本構文

Storage Class Specifier(記憶クラス指定子)

は、文法解析(Parser)の設計を左右する非常に重要なパーツ

Storage Class Specifier(記憶クラス指定子)とは、
C言語の宣言において、変数の「生存期間(Lifetime)」と「連結(Linkage: 他から見えるか)」

を決定するキーワード。


C11では、6つが定義されている。

typedef : 識別子を「型名」として定義する(実態は作らない。)
extern  : 他の場所(別ファイル)で定義された実態を参照する。
static  : 生存期間を静的(プログラムが終了まで)にし、連結(ファイル内)を内部に制限する
auto    : ローカル変数(デフォルト.現代ではほぼ書かれない。)
register: レジスタへの配置を推奨する(アドレス&の取得が禁止される。)
-Thread_local: スレッドごとに独立した記憶領域を持つ。

typedefは文法上、staticやexternと全く同じ仲間として扱われる(Storage Class Specifier)

typedef int  X;
static  int  Y;

文法的には同じ。

「[指定子][型][識別子]」;

書き方の仕様
typedef unsigned long ulong;


typedefって、トップレベルでも使えるし、statementとしても使えるの？？

typedefってのは、変数宣言と全く同じ構文ルール。
そのため、変数宣言がかける場所。（トップレベルでも、関数内のステートメントとしてもかける。）
