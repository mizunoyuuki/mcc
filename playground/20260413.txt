前提
x86-64のレジスタ構造

raxは64bit(8バイト)レジスタですが、その中に小さいレジスタが入れ子になっている。


rax = 64ビット全体(8バイト)
eax = 下位32ビット(4バイト)
al  = 下位8ビット(1バイト)

rdiも同様にedi(32bit) dil(8bit)を持つ。

問題：レジスタは常に64ビット

mccはスタックマシン方式で、値は常にrax(64bit)でやり取りする。
でもメモリ上のデータは方によってサイズが異なる。

メモリ上

int x = 42;   [2A 00 00 00]             4バイト
char c = 'A'; [41]                      1バイト
int *p = ...; [xx xx xx xx xx xx xx xx] 8バイト

ここに矛盾がある。
64bitレジスタに4バイトや1バイトの値を入れる時、残りのビットをどうするか。



### メモリからレジスタに書き込む

ケース１：8バイト(ポインタ)- そのまま
mov rax, [rax]   => メモリから64ビット読んでをraxに入れる
mov [rax], rax   => raxの64bitをメモリに書く

サイズが一致するので、単純なmovで大丈夫


ケース2 : 4バイト(int) - 符号拡張が必要

movsxd rax, dword ptr [rax]

これを分解すると。
- dword ptr [rax] 
 「raxが指すメモリから4バイト(dword)だけよめ」

- movsxd = 「符号拡張(Sign eXtend Dword)して64ビットに広げる」

なぜ符号拡張？ intは符号付き整数だから。

メモリ上の、-1 (int 4バイト) FF FF FF FF

もし単純にraxの下位4バイトに入れると、
rax = 00 00 00 00 FF FF FF FF => 4294967295(馬鹿でかい正の数)

符号ビット(最上位のびっと)を上位32ビットにコピーして埋める。


byte ptr [rax] = raxが指すメモリから1バイトだけよめ。
movsx = 符号拡張(sign extend)して64ビットに広げろ。


### レジスタからメモリに書き込む

ストアでは、64ビットレジスタの中身を全部書いたら、隣のデータを破壊するから。


dword ptr / byte ptr 
これらは、Intel構文のサイズ指定子。メモリのオペランドだけでは何バイト読み書きするのか曖昧な場合に使う。

mov [rax], 42 <- 42を何バイトでストアする？
mov dword ptr [rax], 42 : <- 4バイトでストアする。
mov byte ptr [rax], 42 <- 1バイトでストアする。


レジスタのサイズは、名前できまる。
メモリは[rax]
